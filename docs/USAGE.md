# 使用说明

## 连接与导入

添加主机后选择认证方式：

首次导入成功的新主机会立即尝试连接；重复导入保留已有主机的监控或暂停设置。“恢复监控”使用绿色及外扩光圈，“暂停监控”使用红色光圈。

- **OpenSSH 免密**：复用系统 SSH config、Agent、证书与跳板机，需要系统 `ssh`。
- **内置密钥**：直接选择私钥，不需要系统 OpenSSH。
- **内置密码**：直接连接，可勾选记住密码；再次启动自动取用。

内置模式仅支持直连。复杂 Include、Match、ProxyJump、ProxyCommand 配置请使用 OpenSSH。首次连接核对主机指纹；已记录的密钥发生变化时拒绝连接。

可导入 SSH config 文件、迁移 JSON，也可直接粘贴：

```sshconfig
Host lab-gpu
    HostName gpu.example.com
    User yourname
    Port 22
```

粘贴编辑器在保存前检查语法和必要字段。本程序要求能确定 User；别名还需可解析的 HostName，Port 默认 22。通配条目不是独立主机，编辑器不展开外部 Include，也不校验 Match 条件。导入副本保存在程序数据目录，不修改系统 SSH config。复杂规则可继续使用系统配置。

## 监控与状态

所有启用的主机独立并行监控；选择主机只改变右侧视图。默认每 2 秒采样，可调整为 1–60 秒。网络异常自动退避重连；认证及密钥错误等待人工处理。

GPU 卡片只显示驱动的原生编号，如 `GPU 0`、`GPU 3`，保留跳号，进程表使用相同编号。编号按 UUID 对齐，不以 XML 顺序或设备 minor 代替；查询失败时显示 `—`，恢复采样后刷新编号。

GPU 卡片右上角用同色菱形与文字表示状态：

| 状态 | 含义 |
| --- | --- |
| 空闲 | 通过连续采样确认，未发现计算占用且满足低负载、显存与设备条件 |
| 可用 | 满足配置的资源门槛；可能仍有轻量图形等后台占用 |
| 轻量占用 | 已有可识别计算进程，持续低负载、低显存占用且设备允许共享 |
| 占用 | 超出轻量占用门槛，或进程／计算模式不能确认可共卡 |
| 不可用 | 数据不足、权限不明，或设备报告禁止计算、恢复要求、硬件异常等；具体原因保留 |
| 观察中 | 正在积累连续样本，暂未确认可用 |

默认要求空闲显存至少 4 GiB 且至少占总量 20%，利用率不超过 10%，连续确认至少 10 秒及 3 个样本；具体判断还结合进程和设备状态。“判定规则”可查看和调整门槛。可用数量包含空闲卡。提示不会预留显存或保证任务一定能启动；MIG 物理卡不冒充实例可用性。

轻量占用使用黄色，占用使用深橙色。轻量占用默认还要求占用显存不超过 4 GiB、总显存的 10%，以及利用率不超过 10%；这些上限和剩余显存门槛同时满足，连续确认后计入可用数量，但不计为空闲。仅限 Default 计算模式及信息完整的普通计算进程；MPS、独占模式下的已有上下文、未知进程不作为可共卡。阈值均可在判定规则里调整，已有任务之后仍可能增长。

负载升高立即标为占用；恢复低负载时，确认期内继续保持占用，达标后再切换，避免反复跳入“观察中”。连续满足资源门槛的样本不会因轻量占用／可用等类别变化清零；空闲另需持续无进程。新连接、断采或数据不完整后会重新确认。

暂停条目始终保留，重启后仍暂停。卡片保持暂停前最后采样的状态文字与菱形颜色，下方另标“（暂停监控）”；主机和采样时间标记为历史快照，不计入当前空闲／可用数量。恢复后收到首份成功采样才进入实时状态。旧缓存没有保存状态字段时显示不可用，新的采样会补齐。

暂停卡片保留破口与渐细分叉裂纹，数值和曲线冻结。金色粒子先短促散开，再留下两颗带长尾的热亮滴珠，向下流并冷却渐暗，约 2–3 秒消退；单次仅一簇，避免密集喷发。恢复／暂停按钮使用静态绿／红光圈。切换时逐张点亮或熄灭，内部画面短促触电抖动，无扫描条；恢复后“观察中”确认成具体状态时，还会单独渐亮为对应颜色，正常刷新不重复播放。动画仅覆盖 GPU 卡片，表格不参与转场，状态说明在固定高度内滚动，不挤动周围组件。左侧“显卡 X 张”表示数量，右侧 `GPU X` 表示原生编号。

金色火花在卡片内部随机位置出现，拖尾也被框体裁切。连续快速点击正在监控的 GPU 卡片可使四缸加速；松手后逐渐回落，达到阈值会短暂蓄能，然后爆出冲击环、热亮火团、细密的粉尘喷散与拖尾余烬，最后以渐显、横向信号干扰和拉丝抖动恢复。粉尘消散后露出原有背景，不留下静止框体。爆炸时附带一声轻盈的短促音效，遵循系统音量；不修改采样、远端进程或周围布局，暂停状态不触发。

GPU 点击水波跟随右上角状态的颜色，冻结快照沿用最后状态色；各次点击的水波叠加播放。

日夜模式采用约 0.6 秒交叉淡化，允许中途反向切换；只混合颜色画面，不移动组件。粒子运动参考 [Qt 的重力与阻力模型](https://www.qt.io/product/qt6/qml-book/ch10-effects-affecting-particles)及[拖尾粒子](https://doc.qt.io/qt-6/qml-qtquick-particles-trailemitter.html)的做法，使用现有绘制实现。

最后成功的 GPU、曲线、进程和目录快照写入本地，离线或重启仍能查看。连接中断显示灰色，查询失败不会覆盖最后有效快照。首次连接且没有缓存时等待采样，不生成数据。

点击进程行查看完整目录、可执行文件、用户、UID 和父 PID。容器、hidepid、权限限制或进程已结束时可能无法取得这些信息；程序不会提权、结束进程、读取环境或完整命令行。无 GPU 主机保持连接；AMD／Intel GPU 和远端 Windows 不在支持范围内。

## 配置、密码与迁移

- 默认目录：`%USERPROFILE%\.gpu-checker`，与 EXE 所在目录无关。
- 更新：退出旧程序，再运行新版；重复启动会唤起已运行的实例。
- 便携模式：退出后在 EXE 旁放置空的 `portable.flag`，使用相邻 `data/`。切换前导出配置；保留快照需复制完整原数据目录。
- 私钥支持 `~`、环境变量、绝对路径及相对 EXE 的路径。SSH config 内的路径由 OpenSSH 解释，跨电脑推荐 `~/.ssh/...`。
- “迁移配置”导出主机与 SSH config，不导出程序保存的密码、私钥、私钥口令或信任记录。自定义 SSH 指令内自行写入的秘密需先移除。
- 密码绑定当前 Windows 用户及主机端点，保存在 Windows 凭据管理器；换电脑需重新输入。取消记住密码并保存可删除凭据；私钥口令仅留在会话内存。
- 首次升级会合并旧版 AppData 与包缓存配置并保留备份，避免不同启动环境读取不同列表。明确移除的主机不会重新出现。

程序不会设置系统开机自启，也不要求服务器安装常驻代理。

界面按 Qt 的逻辑像素适配窗口与系统缩放，并根据窗口空间自动选择约 80%–100% 的界面密度，协调缩小字号、卡片、控件高度与留白；放大后恢复，不覆盖系统 DPI 设置。支持 800×500 及以上的可用窗口空间。统计区和 GPU 卡片按宽度重新排列；小屏通过滚动访问完整内容。窗口移到其他屏幕时会收回到该屏幕可用范围，编辑弹窗也支持滚动。

## 开发与诊断

Python 3.11+ x64 运行 `build.ps1`，自动创建虚拟环境、安装锁定依赖、运行测试并生成干净的 EXE／Windows ZIP／源码 ZIP 和 SHA-256 校验文件。发行包不携带开发机器的配置、快照、信任记录或凭据。

```powershell
.\.buildenv\Scripts\python.exe -m pytest tests -q
```

可设置 `GPUCHECKER_DATA_DIR` 使用独立测试目录；该设置优先于便携模式。`GPUChecker.exe --storage-self-test` 只执行配置恢复与诊断，不显示窗口或连接 SSH，输出该数据目录中的 `runtime_state.json`，包含实际物理配置路径和条目数量。

Windows 11 x64 已验证；Windows 10 为目标平台，未独立实测。其他客户端系统／架构和真实 MIG 设备未验证。随包第三方许可证需要一并保留。
